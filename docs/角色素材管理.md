# 角色素材管理

角色身份、本场战斗单位和图片版本分开。禁止按队伍位置或姓名首字猜测图片。

```text
assets/
  characters/
    manifest.json              ← 唯一素材配置真源
    manifest.js                ← 同步脚本生成，不手改
    zhouyu/
      classic/
        generation.json        ← 全身图/头像提示词和生成状态
        fullbody.webp          ← 发布用压缩立绘
        portrait.png           ← 配套头像待生成，目前保留旧头像
      winter/                  ← 未来可增加其他版本
  legacy/
    generals-v1.webp           ← 压缩后的旧头像图集
```

每名武将均有独立目录：周瑜、黄盖、甘宁、鲁肃、诸葛亮、孙权、曹操、张辽、徐晃、于禁、曹仁、吕布。

周瑜已通过内置imagegen单独生成全身图，原画尺寸1024×1536；发布图为1024×1536透明WebP。素材表已标记为就绪，可通过`CharacterAssets.resolve('zhouyu').fullbody`读取。配套独立头像请求返回HTTP429，当前战斗继续使用旧头像。其余人物按用户要求在后续需要时逐个生成。`generation.json`保留工具类型、实际规格、提示词和生成状态，独立素材表将12个人物分别登记。

## 一套角色素材

- `fullbody.webp`：发布图保留原画尺寸，当前为1024×1536，头饰、武器、鞋子完整入画，透明背景。生成原画后运行压缩脚本，不直接发布高清PNG。
- `portrait.png`：该角色配套头像，建议512×768以上，清楚显示头部与上胸。应从同一全身图身份制作，不能重新捏成另一张脸。
- 风格统一，脸、发型、盔帽、服饰颜色相互对应。
- 不覆盖旧版本；新形象放在新版本目录，再改变`defaultVariant`或单位的`artVariant`。

## 替换一名角色

把生成成功的两张图片放入该角色的版本目录，然后将`manifest.json`中这一版本改为：

```json
{
  "label": "基础形象",
  "fullbody": {
    "status": "ready",
    "src": "./assets/characters/zhouyu/classic/fullbody.webp",
    "width": 1024,
    "height": 1536
  },
  "portrait": {
    "status": "ready",
    "src": "./assets/characters/zhouyu/classic/portrait.png",
    "width": 512,
    "height": 768
  }
}
```

原头像来自图集时有`crop`字段；换成独立头像文件后去掉`crop`，不要继续沿用图集坐标。

运行：

```sh
node scripts/sync-assets.cjs
node scripts/build.cjs
```

同步脚本检查已声明就绪的图片确实存在，防止拼错路径后静默串图。未知角色或版本会明确报错，不会返回别人的图片。

调用`CharacterAssets.resolve('zhouyu','classic')`会返回这一版本的头像与立绘；待生成的大图返回null。己方加载`portrait`，敌方优先加载`fullbody`；尚未补齐全身图的旧角色暂用原头像。普通网页按本场阵容加载需要的图片，剧情界面也可按需调用完整立绘。离线单文件演示内嵌已就绪素材，同一位图只嵌入一次。


## 图片压缩（2026-11-04）

发布资源统一使用WebP。全部图片保留原始分辨率：当前人物1024×1536，背景为1024×1536或1536×1024。WebP质量90，透明通道质量100。人物透明通道保留，头像裁切坐标与素材尺寸同步换算；剧情半身像按比例裁切。

新增PNG/JPEG原图并登记素材表后，先运行 `python3 scripts/compress-assets.py`（需要带WebP支持的Pillow），再运行 `node scripts/build.cjs`。压缩脚本更新运行时素材表及场景引用，验证编码结果后移除发布目录中的高清原图；没有新原图时重复运行不会再压缩已有WebP。历史高清图片可从Git历史恢复，generation记录保留原始生成规格与来源。压缩记录见 `assets/compression-report.json`。

当前20张图片从46992373字节降到6382818字节，减少86.4%；普通网页继续按页面和阵容加载图片，离线单文件也只嵌入这些压缩素材。


## 进入游戏前加载

`assets/runtime-manifest.js`由构建脚本生成，记录运行图片的字节数和内容指纹。主菜单和战斗演示都先经过Canvas加载页，按实际接收字节显示进度，完成下载与图片解码后再进入游戏。最多4张图片并发下载，失败可重试，已经成功的图片不再重复下载。

图片按内容指纹缓存，换图后会下载新版本；菜单、剧情和战斗共用预加载的图片，避免再发起一次相同下载。离线版使用内嵌资源，也走同一套解码和进度流程。加载器接受独立资源列表，后续场景可分组调用。

直接打开源码 `index.html`（file://）时改用Image读取本地图片，按已加载文件的字节权重推进，不对本地文件执行fetch，避免CORS拦截。HTTP(S)页面仍按接收到的字节流统计下载进度。
