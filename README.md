# 三国 Canvas 战斗系统

可复用的静态网页战斗组件。战场、角色、血条、读条、技能栏、目标选择、特效、飘字、结算均由单个 Canvas 绘制。赤壁是一组场景数据，系统不写死武将、人数、战场和战斗标题。

## 运行

双击 `启动战斗.command`，或在目录中运行 `python3 -m http.server 8765 --bind 127.0.0.1`，然后访问 `http://127.0.0.1:8765/`。

`dist/index.html` 已内嵌全部代码和图片，可单独保存、离线打开，也可作为 GitHub Pages 的入口。修改源码后运行 `node scripts/build.cjs` 重建，无需安装依赖。

## 操作

进入即按显式技能规则自动战斗，战斗中没有暂停。没有通用普攻和防御指令；没有可用技能时满条待命。数字均不加千位分隔逗号。

- 点己方头像区域或姓名切换自动/手动：自动姓名和边框为蓝色并有轻微待机动效；手动为白色、头像静止待机，四角显示白色标记。
- 满条的手动角色在己方区域水平居中显示技能，一次只显示一人，按准备完成顺序轮换。技能是正方形图标，下方为名称和有颜色的功能标签。
- 单体攻击/治疗/状态技能先选图标，再点高亮目标的头像。群体和自身技能点击即释放。取消目标选择可再次点同一技能或按 Escape。
- 再点己方头像或姓名可恢复自动；其他人持续战斗。长按头像约1秒打开居中的施法设置，通过横向滑条修改群攻人数、治疗阈值、技能开关和四种输出目标；百分比每档1%，滑到最左端仍保留正常交互颜色；保存前为草稿，设置期间不暂停。
- 技能名称在施法者头顶飘起，伤害/回复数字在目标头顶飘起；支持火、雷、木、水、土攻击特效、绿色回复、增益/减益、头像受击红闪、前冲/后仰、命中闪光和暴击震屏。血条主条平滑变化，白条延迟追赶；治疗平滑增长。
- 战后可查看战报、计算因子和重开。战斗中没有指挥弹窗、菜单、确认按钮或倍率栏。

## 接入及验证场景

参见 [战斗系统接入.md](./战斗系统接入.md)。

- 默认：赤壁五对五，常规自动战斗。
- `?scenario=encounter`：不同标题、阵容、等级和场地的独立遭遇战，验证复用。
- `?scenario=effects`：特效和操作验证，五名己方初始手动，涵盖五种攻击效果、单/群治疗、自身/友军/敌军状态；使用耐久目标和测试数值，不是正式技能表或数值平衡。

手机375×667和320×568尺寸已实际检查，包括居中设置窗口；超员布局有几何检查。尚未做真机触控测试。

## 结构

- `js/presentation.js`：无逗号数字、血条连续动画和延迟白条。
- `js/character-assets.js`：角色ID与形象版本的独立素材解析。
- `assets/characters/manifest.json`：角色素材真源，改完运行`node scripts/sync-assets.cjs`。
- `js/engine.js`：不依赖DOM的战斗引擎；传入双方阵容、规则、技能和场景元数据。
- `js/rules.js`：伤害、技能基础定义及通用默认规则。
- `js/canvas-battle.js`：Canvas绘制、姓名切换、居中单人技能栏、点选和战后复盘。
- `js/canvas-effects.js`：五种攻击元素、治疗、Buff/Debuff、红闪与震屏。
- `js/data.js`：演示武将与场景工厂；可由正式游戏的剧情系统替换。
- `js/app.js`：演示入口，只负责选择场景并调用组件。
- `assets/README.md`：内置imagegen生成素材及提示词记录。

运行 `node --test tests/*.test.cjs`。当前46项检查覆盖公式、时序、资源、守恒、超员、场景隔离、定制技能、手动释放、状态到期、自动恢复、1%阈值保存和头像等比缩放。

伤害基础参考既有《吞食天地2》研究；护甲/抗性已按用户新决定统一为K/(K+对应防护)，演示K=100，覆盖旧防御公式。仅物理技能受护甲影响，仅计策技能受抗性影响，治疗不减。数值和系数均非最终平衡值。详见 [战斗数值设计.md](./战斗数值设计.md) 和 [游戏设定.md](./游戏设定.md)。

将源码目录或单文件版放到 GitHub Pages 即可；本轮未推送或部署。


## 素材进度

角色素材已拆成独立角色ID和版本配置，战斗只引用头像，后续全身图按需载入。现有头像暂存于`assets/legacy/generals-v1.png`，各角色素材表分别记录裁剪信息；不存在按阵容位置猜测头像的逻辑。

周瑜的独立全身图已生成并保存为`assets/characters/zhouyu/classic/fullbody.png`（1024×1536 RGBA）；配套独立头像请求返回HTTP429，战斗头像暂用旧图。其余人物按需逐个生成。各角色目录保留提示词和生成状态，管理方式见[角色素材管理.md](./角色素材管理.md)。


输出技能不再使用自身或目标血量作为施放条件：单体输出仅设从不/始终，群攻仅设至少几人。治疗仍分别设置自身和队友兵力阈值，嘲讽可设置始终。

自动施法规则核对与本作适配见[自动施法规则.md](./自动施法规则.md)。新版自测覆盖群攻优先、两个单体技能轮换、自身/队友分别治疗、四种目标、嘲讽缺失补充、设置草稿和待机状态。


## 同步施法性能

已加入背景缓存、头像/受击纹理预热、文字缓存和特效动画帧缓存。同一目标相同属性的重复光效合并；战斗计算与完整战报不合并、不省略。输入只修改状态，每帧只统一绘制一次；待命AI只在战场或设置变化后重新判断。

`?scenario=stress&profile=1`用于十人同时群攻的压力验证。统计写在Canvas的`data-frame-stats`，不增加游戏界面内容。测量记录见[性能测试.md](./性能测试.md)。

移除原有输出血量限制后，旧的赤壁参数会出现联军失利，这是按新逻辑模拟的结果；当前演示数值仍未作正式平衡。
